# Gouvernance HP Travail

## Principe de contrôle

Les retours utilisateurs (idées, suggestions, rapports d'erreur, crashs) sont uniquement des informations à examiner.

Aucun retour utilisateur ne constitue une autorisation de modifier le code, la structure, le design, les fonctionnalités, les paramètres de publication ou le système de mise à jour de HP Travail.

Toute modification de l'application nécessite l'approbation explicite du propriétaire du dépôt avant écriture dans le code ou publication d'une nouvelle version.

## Règles obligatoires

- Les utilisateurs peuvent uniquement envoyer des idées et rapports techniques.
- Aucun mécanisme de feedback ne doit disposer d'un jeton GitHub avec droits d'écriture.
- Aucun système automatisé ne doit créer, fusionner ou publier une modification à partir d'un feedback sans approbation explicite du propriétaire.
- Les rapports de crash peuvent être analysés et regroupés automatiquement, mais toute correction du code doit être approuvée par le propriétaire.
- Les suggestions peuvent être classées, résumées et priorisées, mais elles restent non exécutoires.
- Les clés de signature et secrets GitHub restent uniquement côté GitHub Actions / dépôt sécurisé et ne doivent jamais être intégrés dans l'APK.

## Données

Les rapports techniques ne doivent pas inclure l'historique de pointage, les adresses enregistrées, les données GPS enregistrées, les salaires ou autres données professionnelles privées. Le texte d'une idée est envoyé uniquement lorsque l'utilisateur appuie volontairement sur le bouton d'envoi.
